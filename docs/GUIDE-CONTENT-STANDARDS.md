## Суть за 30 секунд

Краткое изложение статьи (2-4 предложения). Должно содержать:
- Основную мысль
- Ключевой вывод
- Практическую пользу

## Основной текст

### Теоретическая часть

Объяснение концепции с опорой на научные источники.

**Требования:**
- Каждое утверждение marked как **[ДОКАЗАНО]**, **[ПОДДЕРЖАНО]** или **[ГИПОТЕЗА]**
- Ссылки на исследования (автор, год)
- Примеры из практики (с контекстом)

### Доказательная база

Блок с цитатами и ссылками на исследования.

---

## Как на самом деле

Разрушение мифов и распространённых заблуждений.

**Формат:**
```markdown
❌ **«Миф или заблуждение»**
✅ **Правильное понимание**
```

**Позиция:** Этот блок идёт **ДО** блока "Что делать".

---

## Что делать

Практические рекомендации для применения концепции.

**Требования:**
- **ОДИН блок** "Что делать" в конце статьи
- 3-5 конкретных шагов
- Каждый шаг — действие, которое можно выполнить сразу
- Ссылки на инструменты eyeCARD где уместно

**Позиция:** Этот блок идёт **ПОСЛЕ** блока "Как на самом деле".

## 🚫 Запрещённые паттерны

### 1. Дублирование блоков "Что делать"

**Запрещено:** Иметь более одного блока "Что делать" в статье.

**Почему:** Дублирование confusing для читателя и размывает фокус рекомендаций.

**Решение:** Объединить все рекомендации в один блок в конце статьи.

---

### 2. Изолированные кейсы без контекста

**Запрещено:** Упоминать конкретные товары (артикулы) без полного контекста.

**Почему:** Без изображения карточки, описания товара и результатов анализа — это галлюцинация, которая не несёт пользы читателю.

**Правило:** Кейс с упоминанием товара **обязан** включать:

```markdown
### Кейс: [Название товара]

**Площадка:** Wildberries / Ozon  
**Артикул:** XXXXXXX  
**Категория:** [Категория товара]

**Исходная карточка:**
![Описание изображения](ссылка)

**Анализ eyeCARD:**
- ICC: XX
- Доминирующий радикал: [Название]
- Выявленные проблемы: [Список]

**Рекомендации:**
1. [Рекомендация 1]
2. [Рекомендация 2]

**Результат:**
[Описание изменений и эффекта]
```

**Если контекста нет — кейс удаляется.**

---

### 3. Неправильный порядок блоков

**Запрещено:** Размещать блок "Что делать" **ДО** блока "Как на самом деле".

**Почему:** Логика статьи требует сначала разрушить мифы, затем дать практические рекомендации.

**Правильный порядок:**
1. Суть за 30 секунд
2. Основной текст (теория)
3. **Как на самом деле** (разрушение мифов)
4. **Что делать** (практические рекомендации)
5. Читайте также

## ✅ Чек-лист качества статьи

Перед публикацией статья **обязана** пройти проверку:

- [ ] Структура соответствует стандарту
- [ ] Есть блок "Суть за 30 секунд"
- [ ] Есть блок "Как на самом деле" (если применимо)
- [ ] Есть **один** блок "Что делать" в конце
- [ ] Порядок блоков правильный
- [ ] Нет изолированных кейсов без контекста
- [ ] Все утверждения marked ([ДОКАЗАНО]/[ПОДДЕРЖАНО]/[ГИПОТЕЗА])
- [ ] Есть ссылки на научные источники
- [ ] Есть cross-links на связанные статьи
- [ ] Время чтения указано корректно

## 📝 Процесс внесения изменений

### 1. Обнаружение проблемы

- Автоматическая проверка (`find-hallucinations.mjs`)
- Ручная проверка при чтении статьи
- Обратная связь от пользователей

### 2. Создание ветки

```bash
git worktree add ../guide-fix-X.X.X -b fix/guide-X.X.X
```

### 3. Внесение изменений

- Исправить проблему в `docs/reference/Tasks/doc-X.X.X.md`
- Запустить проверку: `node scripts/find-hallucinations.mjs`
- Убедиться, что проблема устранена

### 4. Пересборка guide

```bash
npm run build:guide
```

### 5. Тестирование

```bash
npm run dev
```

Проверить страницу `http://localhost:3000/guide/X.X.X`

### 6. Коммит и merge

```bash
git add -A
git commit -m "fix: исправить галлюцинации в guide X.X.X"
git push origin fix/guide-X.X.X
```

Создать PR и merge в `main`.
