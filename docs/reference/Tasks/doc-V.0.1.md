# Документ V.0.1. Как устроен анализ: технический путевой лист

**Код:** V.0.1
**Раздел:** V. Визуальный паспорт: декодер → V.0 Как устроен анализ
**Время чтения:** 5 мин

---

## Суть за 30 секунд

Анализ eyeCARD — это 4-фазный конвейер в GCP Workflows (9 шагов): ИИ извлекает визуальные признаки, классифицирует их по слоям, детерминированный Math Engine считает векторы и ICC, затем ИИ формирует вердикт. Результат стабилен: при одинаковых входных данных анализ даёт одинаковый результат. Этот документ объясняет, как устроен конвейер «под капотом».

---

## Основной текст

### Общая схема конвейера

```
┌─────────────────────────────────────────────────────────────┐
│                    ВИЗУАЛЬНЫЙ ПАСПОРТ                        │
│                 (итоговый JSON + отчёт)                      │
└─────────────────────────────────────────────────────────────┘
                            ↑
                    ┌───────────────┐
                    │   ФАЗА P4     │  ← LLM-аудит
                    │  (ИИ + код)   │     (вердикт, степень расхождения)
                    └───────────────┘
                            ↑
                    ┌───────────────┐
                    │  MATH ENGINE  │  ← Детерминированный алгоритм
                    │   (ФАЗА P3)   │     (нормировка, ICC, векторы)
                    └───────────────┘
                            ↑
                    ┌───────────────┐
                    │   ФАЗА P2     │  ← Классификация признаков
                    │    (ИИ)       │     (8 полюсов, 12 архетипов, 7 радикалов)
                    └───────────────┘
                            ↑
                    ┌───────────────┐
                    │   ФАЗА P1     │  ← Извлечение признаков
                    │    (ИИ)       │     (что видит ИИ на карточке)
                    └───────────────┘
                            ↑
                    ┌─────────────────┐
                    │   ВХОДНЫЕ       │
                    │   ДАННЫЕ        │  ← Изображение карточки (ArrayBuffer)
                    └─────────────────┘
```

### Фаза P1: Mapping (Извлечение признаков)

**Что делает:** ИИ анализирует изображение карточки и извлекает визуальные признаки: цвета, формы, композицию, шрифты, фото, текстуры.

**Ключевые шаги:**
- **p1_3 Ideal Axis:** семантическая ось + вектор + архетипы ИДЕАЛА (какой психотип у целевой аудитории этого товара?)
- **p1_4 Ideal Radical:** ведущий и вспомогательные радикалы ИДЕАЛА

**Модель:** qwen3.8-omni-flash (DashScope)
**Температура:** 0 (минимальная случайность)
**Результат:** JSON с сырыми признаками + профиль ИДЕАЛА

---

### Фаза P2: Sorting (Классификация признаков)

**Что делает:** ИИ классифицирует извлечённые признаки по трём измерениям:

1. **p2_1:** распределение визуальных маркеров дизайна по 8 полюсам (4 оси × 2 полюса)
2. **p2_2:** распределение по 12 архетипам
3. **p2_3:** распределение по 7 радикалам

**Результат:** профиль ФАКТА (какой психотип у текущего дизайна карточки?)

---

### Фаза P3: Math Engine (Детерминированный алгоритм)

**Что делает:** Python-скрипт на FastAPI (Cloud Run) выполняет:

#### 1. Нормировка counts в проценты

Сырые счётчики маркеров нормируются по весам к единой шкале 0–100% для сравнимости между карточками.

#### 2. Расчёт 4 семантических векторов

На основе классифицированных признаков вычисляются 4 оси (по 2 полюса каждая):

| Ось | Полюс A | Полюс B |
|-----|---------|---------|
| **Структура** | Стабильность | Изменения |
| **Социальность** | Индивидуализм | Принадлежность |
| **Реализация** | Мастерство | Служение |
| **Ментальность** | Рациональность | Эмоциональность |

Каждый полюс получает процент силы 0–100. В ИДЕАЛ-векторе целевой полюс (vector.end из p1_3) получает 100, остальные — 0; ФАКТ-вектор строится из нормированных счётчиков маркеров дизайна.

#### 3. Расчёт ICC (Индекс Когнитивного Комфорта)

ICC — отклонение фактического числа маркеров ведущего радикала от эталонного веса: штраф = |факт − эталон| / эталон, ICC = (1 − штраф) × 100.

**Диапазон:** 0–100
- **0–25** — Плохой (визуальный хаос)
- **25–50** — Слабый (много шума)
- **50–75** — Средний (приемлемо, есть запас)
- **75–100** — Хороший (чистый дизайн)

**Версия алгоритма нормировки:** Soft Clamping V2.1

**Статус:** **Детерминированный алгоритм** (не промпт, не ИИ). При одинаковых входных данных результат всегда одинаковый.

---

### Фаза P4: Verdict (LLM-аудит)

**Что делает:** ИИ сравнивает ИДЕАЛ и ФАКТ профили и генерирует:
- Вердикт (СООТВЕТСТВУЕТ / ЧАСТИЧНО СООТВЕТСТВУЕТ / ПРОТИВОРЕЧИТ)
- Степень расхождения (минимальная / умеренная / критическая) + обоснование
- Влияние на продажи

Evidence-блоки (обоснования модулей СМЫСЛЫ / АРХЕТИПЫ / РАДИКАЛЫ) генерируются ещё на фазе P1 (axis_evidence, archetype_evidence, radical_evidence) и проходят в паспорт без изменений.

**Результат:** Визуальный паспорт (JSON + HTML/PNG)

### Почему результат стабилен

**Math Engine (фаза P3)** — детерминированный алгоритм:
- Нет ИИ-промптов
- Нет случайности
- При одинаковых входных данных результат всегда одинаковый

**ИИ-фазы (P1, P2, P4)** — с температурой 0:
- Температура 0 = минимальная случайность
- Чёткие промпты с шаблонами
- Валидация результата

**Итог:** при одинаковых входных данных анализ даёт одинаковый результат (с точностью до незначительных колебаний ИИ).

## Как на самом деле

❌ **«Анализ — это один промпт ИИ»**

✅ Анализ — это 4-фазный конвейер: 3 ИИ-фазы + 1 детерминированный алгоритм.

❌ **«Результат каждый раз разный»**

✅ Math Engine (фаза P3) — детерминированный алгоритм. Результат стабилен.

❌ **«ICC — это субъективная оценка»**

✅ ICC — объективная метрика: отклонение числа маркеров ведущего радикала от эталона, а не «мнение ИИ».

❌ **«Векторы — это магия»**

✅ Векторы — результат математических расчётов на основе классифицированных признаков.

## Что делать

1. **Понимайте схему** — 4 фазы: P1 (Mapping) → P2 (Sorting) → P3 (Math Engine) → P4 (Verdict).
2. **Знайте, где ИИ, где код** — Math Engine детерминирован, ИИ-фазы — с температурой 0.
3. **Следите за версиями** — методика эволюционирует (changelog).
4. **Сверяйте версию методики в шапке паспорта** — она указывает, какая логика анализа применялась.
5. **Помните о гарантии стабильности** — одинаковые входные данные дают одинаковый результат.
