# Документ VI.5.1. Шаблон ТЗ дизайнеру на данных eyeCARD

**Код:** VI.5.1
**Раздел:** VI. Практика: от паспорта к продажам → VI.5 Сценарий: бриф дизайнера и фотобанк
**Время чтения:** 5 мин
**Тип:** Практический фреймворк [П]

---

## Суть за 30 секунд

Визуальный паспорт eyeCARD — готовое ТЗ для дизайнера. Вместо абстрактных пожеланий («сделайте красиво») вы даёте дизайнеру конкретные данные: целевой радикал/архетип, слои-приоритеты (из матрицы III.8.2), критерии приёмки (повторный анализ через eyeCARD). Шаблон ТЗ превращает паспорт в технический документ, который дизайнер может выполнить без дополнительных вопросов.

---

## Основной текст

### Зачем нужно ТЗ на данных eyeCARD

**Проблема:** селлер говорит дизайнеру «сделайте красиво» — дизайнер делает «как умеет» — результат не попадает в целевую аудиторию — деньги потрачены, продажи не выросли.

**Решение:** ТЗ на данных eyeCARD даёт дизайнеру **конкретные параметры**:
- **Целевой радикал** — для кого дизайн (Эпилептоид, Истероид и т.д.)
- **Целевой архетип** — какую роль играет товар (Маг, Герой и т.д.)
- **Слои-приоритеты** — какие визуальные элементы важны (цвет, формы, шрифты, композиция, графика, сюжет)
- **Критерии приёмки** — как проверить результат (повторный анализ через eyeCARD)

```markdown

## 3. Приоритеты слоёв (из матрицы III.8.2)

### 3.3. Типографика (шрифты)

- **Целевая графика:** [например, таблицы, иконки, сертификаты]

- **Обязательные маркеры:** [например, матовые фактуры, строгая сетка, таблицы характеристик, ГОСТ, сертификаты]
```

```markdown
# Техническое задание на дизайн карточки товара

## 1. Общая информация
- **Товар:** Тонометр автоматический [название]
- **Артикул:** OZON 123456789
- **Категория:** Здоровье → Тонометры
- **Дата:** 2026-08-31

- **Ведущий радикал:** Эпилептоид
- **Вспомогательный радикал:** Тревожный
- **Базовый архетип:** Мудрец
- **Оттеночный архетип:** Заботливый

## 3. Приоритеты слоёв (из матрицы III.8.2)

### 3.1. Хроматика (цвет)
- **Целевая гамма:** холодная гамма, матовые тона (синий, серый, белый)
- **Акцентный цвет:** тёмно-синий (oklch(34.25% 0.057 252.12))
- **Запрещённые цвета:** неон, яркие кислотные тона (красный, жёлтый, оранжевый)

### 3.2. Морфология (формы)
- **Целевые формы:** строгие прямоугольники, симметрия, чёткие линии
- **Запрещённые формы:** асимметрия, диагонали, звёзды, скруглённые углы

### 3.3. Типографика (шрифты)
- **Целевые шрифты:** гротески, средний вес (например, Inter, Roboto)
- **Запрещённые шрифты:** курсив, рукописные, 3D-эффекты, засечки

### 3.4. Архитектоника (композиция)
- **Целевая композиция:** строгая сетка, чёткая иерархия (название → выгода → характеристики)
- **Запрещённая композиция:** хаос, нагромождение элементов, отсутствие иерархии

### 3.5. Графика (инфографика/декор)
- **Целевая графика:** таблицы характеристик, иконки (сердце, давление), бейджи «ГОСТ», «Сертификат»
- **Запрещённая графика:** звёздочки, восклицательные знаки, «СКИДКА 90%», блёстки

### 3.6. Сюжет (фото-контекст)
- **Целевой сюжет:** изолят на белом фоне, технические ракурсы (сверху, сбоку), макро деталей
- **Запрещённый сюжет:** lifestyle с лицами, эмоциональные сцены, «человек использует товар»

## 4. Визуальные маркеры радикала (из матрицы III.8.2)
- **Обязательные маркеры:** матовые фактуры, строгая сетка, таблицы характеристик, ГОСТ, сертификаты, гарантийные бейджи
- **Запрещённые маркеры:** неон, 3D-эффекты, «СКИДКА 90%», звёзды, восклицательные знаки

## 5. Критерии приёмки
- **Повторный анализ через eyeCARD:** после сдачи работы карточка должна быть проанализирована через eyeCARD.
- **Критерий успеха:** ведущий радикал (Эпилептоид) считывается с уверенностью ≥70% (СИГНАЛ УВЕРЕННЫЙ или ЭТАЛОННЫЙ).
- **Критерий провала:** ведущий радикал считывается с уверенностью <50% (СИГНАЛ СМЕШАННЫЙ) — работа возвращается на доработку.

## 6. Референсы
- **Положительные референсы:** [ссылка на карточку тонометра с эпилептоидным дизайном]
- **Отрицательные референсы:** [ссылка на карточку тонометра с истероидным дизайном]
```

### Как работать с ТЗ

1. **Заполните шаблон** — используйте данные из паспорта eyeCARD и матрицу III.8.2.

2. **Отправьте дизайнеру** — вместе с ТЗ отправьте ссылку на паспорт eyeCARD, чтобы дизайнер мог посмотреть исходные данные.

3. **Проведите установочную встречу** — объясните дизайнеру, что такое радикал и архетип, почему это важно.

4. **Принимайте работу через eyeCARD** — после сдачи работы проанализируйте карточку через eyeCARD. Если ведущий радикал считывается с уверенностью ≥70% — работа принята. Если <50% — работа возвращается на доработку.

5. **Оплачивайте по результату** — оплата после успешного повторного анализа. Это мотивирует дизайнера делать работу качественно.

---

## Частые ошибки

1. **Не указывать критерии приёмки** — дизайнер не знает, как проверить результат. Всегда указывайте: «повторный анализ через eyeCARD, критерий успеха — СИГНАЛ УВЕРЕННЫЙ или ЭТАЛОННЫЙ».

2. **Давать абстрактные пожелания** — «сделайте красиво» не работает. Давайте конкретные параметры: «холодная гамма, матовые тона, строгая сетка».

3. **Не давать референсы** — дизайнер может не понять, что такое «эпилептоидный дизайн». Давайте положительные и отрицательные референсы.

4. **Не проводить установочную встречу** — дизайнер может не знать терминологию eyeCARD. Объясните, что такое радикал и архетип.
